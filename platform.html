Platform

Everything is a view of one object: the assessment.

The conversation held, the score proposed, the confidence attached to it, the examiner who adjudicated it and the rubric and engine versions in force are all properties of a single assessment record.

Development stage: pre-pilot · what this means

Architecture

One assessment. Five layers of trust.

Most automated assessment has an interface and a scoring engine. The proposed AngliaAI design adds assurance, a permanent human layer and a sealed record beneath them.

Select a layer. Use the arrow keys to move between layers.

Layer 3 of 5

Assurance

A confidence gate, standard-drift monitoring, cohort fairness monitoring and generation of the validity evidence pack.

Why it exists

This layer is designed to turn a score into a decision an institution can defend to its own quality committee or auditor.

  • Confidence gate
  • Drift monitoring
  • Fairness monitoring
  • Evidence pack

  1. L1Conversation

    An adaptive two-way conversation that follows up on what the candidate actually says, so no two interviews are identical.

    • Adaptive follow-up questions
    • Unscored warm-up
    • Live transcript
    • Reasonable adjustments

  2. L2Scoring & Calibration

    Scores against the client’s own rubric through a versioned calibration profile built from the client’s marked exemplars.

    • Rubric ingestion
    • Calibration profile
    • Marked exemplars
    • Version control

  3. L3Assurance

    Differentiator

    A confidence gate, standard-drift monitoring, cohort fairness monitoring and generation of the validity evidence pack.

    • Confidence gate
    • Drift monitoring
    • Fairness monitoring
    • Evidence pack

  4. L4Human Examiner

    Certified examiners adjudicate low-confidence cases and handle appeals. The human layer is permanent, not transitional.

    • Adjudication queue
    • Appeals
    • Re-marking
    • Examiner notes

  5. L5Record

    Sealed assessment records pinned to the engine version, calibration profile and rubric in force at the time.

    • Sealed records
    • Version pinning
    • Immutable audit log
    • Evidence export

Proposed product architecture. Capabilities are subject to validation and roadmap delivery.

The confidence gate

One mechanism, four jobs.

The gate sits between the proposed score and the released result. It is the centre of the design.

  1. 01

    Decides which results release automatically

    Delivers the speed and capacity the organisation is looking for.

  2. 02

    Decides which cases a human sees

    Keeps a certified examiner in the loop where a decision carries significant effects for an individual.

  3. 03

    Builds adjudicated reference data

    Every case an examiner resolves becomes ground truth for future calibration.

  4. 04

    Is tunable for each client

    A risk-averse awarding body can set it conservatively. A low-stakes diagnostic can set it more loosely.

Product experience

Four screens carry the product.

Two principles govern each of them. Manage by exception: staff see the cases the engine is unsure about, not a dashboard of everything. Never hide a limitation: confidence sits beside every score, and adverse findings are shown as prominently as favourable ones.

Concept interfaces. Every number shown is illustrative; none is drawn from a live deployment.

The assessment lifecycle

Designed so a result can be defended years later.

Exception states are designed, not bolted on

Under review, under appeal and re-marked are states with defined entry and exit conditions.

A released result is never edited

It is superseded. Both versions survive, both are timestamped, and the log records who changed what and why.

Every transition is written to the record

Actor, timestamp, engine version and calibration profile version are stored with each change.

How it scales

Adjudicated cases are intended to improve the system that produced them.

Each case a certified examiner resolves can improve the calibration profile, so fewer cases should reach the gate in the next cycle. If that holds, cost falls and evidence strengthens from the same event.

  1. 01More assessments
  2. 02More adjudicated cases
  3. 03Larger ground-truth corpus
  4. 04Better calibration
  5. 05Fewer cases requiring human intervention
  6. 06Lower marginal cost
  7. 07Stronger evidence
  8. 08More institutional adoption
  9. ↺…and back to more assessments.

This is the central assumption to be tested. If the share of cases needing a human does not fall as the corpus grows, the scalability case weakens. It will be measured from the first pilot.
